# Process Specification

## Purpose

This specification defines the canonical representation of processes within Zoryn.

Processes are the primary mechanisms that generate change.

Processes are inferred from evidence.

Processes evolve continuously.

---

# Definition

A process is a persistent mechanism that transforms one or more
Earth system states through time.

Processes are not directly observed.

They are inferred.

---

# Canonical Structure

Every process contains

Process Identifier

Process Type

Ontology Concept

Supporting Evidence

Inputs

Outputs

Spatial Scope

Temporal Scope

Confidence

Status

Version

---

# Process Identifier

Every process possesses a globally unique identifier.

Identifiers never change.

---

# Process Type

Examples include

Physical

Biological

Human

Infrastructure

Knowledge

Unknown

Each process belongs to exactly one primary type.

---

# Ontology Concept

Every process references one ontology concept.

The ontology defines the scientific meaning of the process.

---

# Supporting Evidence

Processes are supported by evidence.

Evidence consists of one or more facts.

Evidence accumulates continuously.

Every process therefore has an evidence graph.

---

# Inputs

Inputs describe what influences a process.

Examples

Rainfall

Temperature

River Flow

Population

Market Price

Inputs may themselves be generated by other processes.

---

# Outputs

Outputs describe observable consequences.

Examples

Runoff

Vegetation Growth

Migration

Crop Yield

Reservoir Storage

Outputs become evidence for downstream processes.

---

# Spatial Scope

Processes operate across space.

Possible scopes include

Point

Grid Cell

Catchment

Region

Country

Global

Spatial extent may evolve through time.

---

# Temporal Scope

Processes operate through time.

Examples

Instantaneous

Continuous

Seasonal

Periodic

Persistent

Temporal behaviour is itself observable.

---

# Confidence

Confidence reflects current scientific support.

Confidence changes only through new evidence.

Historical confidence is preserved.

---

# Status

A process may be

Candidate

Validated

Deprecated

Rejected

Archived

Status changes generate new facts.

Status never overwrites history.

---

# Version

Versions describe changes to the process definition.

Observed behaviour remains unchanged.

Historical interpretations remain reproducible.

---

# Constraints

Every process

must possess supporting evidence,

must reference an ontology concept,

must define inputs,

must define outputs,

must possess temporal meaning,

must possess spatial meaning,

must preserve provenance.

---

# Design Principles

1. Processes are inferred.
2. Processes explain change.
3. Processes accumulate evidence.
4. Processes evolve continuously.
5. Unknown processes are expected.
6. Process confidence is evidence driven.
7. Processes remain reproducible.
8. Discovery never stops.
